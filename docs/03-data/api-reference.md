# API reference

Every function the apps can call. This list **is** the public surface of the
platform: there is no other way in
([decision 1](../02-architecture/decisions.md#1-database-functions-are-the-public-api)).

Generated by reading `supabase/migrations/` — 146 functions in `public`, each
with an explicit grant. If a function is added and this page is not updated,
the count in the last section will be wrong; that is the check.

**How to read it**

- **Who may call it** is the rule enforced inside the function or by the
  policies under it — not just the grant. Every function granted to
  `authenticated` can be _invoked_ by any signed-in user; what it does for them
  is another matter.
- **Mode**: _invoker_ runs with the caller's own row access, so it cannot
  return more than row-level security allows. _Definer_ runs with elevated
  rights and checks the caller itself.
- "Staff: ops" means an active staff member with that role, or admin; and,
  when `require_staff_mfa` is on, a session with a second factor.
- **The second factor counts in the database.** A staff member or seller who
  has a verified second factor gets nothing from a staff or seller function,
  or from a seller policy, with a password-only (`aal1`) session, whatever
  `require_staff_mfa` says. Before every request the Data API also runs
  `check_request()` (below), which refuses a deleted account, an ended session
  (`session_ended`), and a password-only session of any account with a factor
  for everything except the second-step functions (`second_factor_required`).
- A caller who is not allowed gets the error code `forbidden`, or — for
  something that belongs to another person — the same "not found" as if it did
  not exist.
- The typed client is `packages/db/src/api.ts`: each function has a camelCase
  method (`place_order` → `placeOrder`) and a response schema in `schemas.ts`.

### Account security

Supabase Auth itself does passwords, sessions, e-mail confirmation and the
time-based codes; these are what the database adds.

| Function                         | Mode    | Who may call it | Returns or does                                                                                                                                                                                                                                                                                                                                                                                                                                |
| -------------------------------- | ------- | --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `my_security()`                  | Definer | Self            | `{aal, is_staff, mfa_required, staff_session_ok}`. Works before the second step, so the apps know to ask for it                                                                                                                                                                                                                                                                                                                                |
| `mfa_attempt_status()`           | Definer | Self            | `{locked, attempts_left, retry_after_seconds}`: five wrong second-factor codes in 15 minutes lock the second step for the rest of those 15 minutes                                                                                                                                                                                                                                                                                             |
| `mfa_reserve_attempt()`          | Definer | Self            | Called before every code the apps send to Auth. Counts the attempt at once, under a per-account lock, and returns the status plus `attempt_id`, which is null when the account is locked (the code must not be sent). It replaces `mfa_record_failure`                                                                                                                                                                                         |
| `mfa_attempt_succeeded(attempt)` | Definer | Self            | After Auth accepted the code: removes that reservation, only one's own, only from a session that passed the second step (`second_factor_required` otherwise)                                                                                                                                                                                                                                                                                   |
| `account_deletion_check()`       | Definer | Self            | `{blockers, orders_kept, reviews_kept}`: what stands in the way of deleting the account, in the order to deal with it. Needs the second step if the account has a factor                                                                                                                                                                                                                                                                       |
| `delete_my_account()`            | Definer | Self            | Deletes the account in one transaction, or raises the first blocker. What is erased and what is kept (anonymised) is in [privacy](../05-security-compliance/privacy.md#deleting-an-account); it includes the person's notification settings, consent history, push tokens and suppressions, and closes a shop left with nobody in charge, with its photos. Blockers, in order: `account_is_staff`, `account_is_driver`,
`account_is_warehouse_staff`, `account_has_open_orders`,
`account_has_open_returns`, `account_has_pending_refund`,
`account_has_open_complaints`, `account_runs_open_shop`,
`account_shop_has_stock`, `account_shop_has_open_orders`,
`account_shop_has_balance`.

## Files

Product photos are files in Supabase Storage, not rows. Two buckets, created
by `20261121082700_product_photos.sql`: `product-photos-pending` (private,
what sellers upload) and `product-photos` (public, approved photos only), each
limited to 2 MiB and JPEG, PNG or WebP. Rules on `storage.objects` decide, as
the caller:

- **Add**: a member of the shop, only the three file names of a photo it
  reserved, within two hours, never as a replacement (`x-upsert` is refused);
  in the public bucket only catalogue staff, for an approved photo.
- **Read**: catalogue staff, anything; a member of the shop, only by
  downloading (never signing a link, listing, copying or moving), only in the
  private bucket and only files of a photo under review.
- **Delete**: what the read rule allows and nothing needs any more.
- Storage does not run `check_request`, so each rule first checks the same
  things itself: the account exists, the session has not ended, and a
  password-only session of an account with a factor gets nothing.

## Errors

A refused or failed call raises SQLSTATE `P0001` with a short machine-readable
code as its message, sometimes with a detail value (the offer that ran out,
the date a window closed). The complete list, with the text shown to a person
in Spanish and English, is `packages/db/src/errors.ts`. A unit test
(`errors.test.ts`) reads every `private.fail('…')` in the migrations and fails
if a code has no message or a message has no code.

The client turns any such failure into an `ApiError` with `code`, `detail` and
`userMessage(locale)`. Unexpected errors — a network failure, a response that
does not match its schema — become `network` or `invalid_response` and are
never shown verbatim.

## Keeping this page honest

To list the functions and their grants as the database has them:

```sql
select p.proname,
       case when p.prosecdef then 'definer' else 'invoker' end as mode,
       has_function_privilege('anon', p.oid, 'execute') as visitors,
       has_function_privilege('authenticated', p.oid, 'execute') as signed_in
from pg_proc p
join pg_namespace n on n.oid = p.pronamespace
where n.nspname = 'public' and p.prokind = 'f'
order by 1;
```

At the time of writing: 146 functions, 12 of them open to visitors (11 the
apps call, plus `check_request`), 135 callable by signed-in users subject to
their own checks, and 11 for one server-side role only (10 `worker_*` for
`service_role`, the Auth hook for `supabase_auth_admin`). A function in
`public` that appears here without a grant line in a migration, or a grant to
visitors that is not in the first table above, is a defect.
