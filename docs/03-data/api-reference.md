# API reference

Every function the apps can call. This list **is** the public surface of the
platform: there is no other way in
([decision 1](../02-architecture/decisions.md#1-database-functions-are-the-public-api)).

Generated by reading `supabase/migrations/` — 77 functions in `public`, each
with an explicit grant. If a function is added and this page is not updated,
the count in the last section will be wrong; that is the check.

**How to read it**

- **Who may call it** is the rule enforced inside the function or by the
  policies under it — not just the grant. Every function granted to
  `authenticated` can be _invoked_ by any signed-in user; what it does for them
  is another matter.
- **Mode**: _invoker_ runs with the caller's own row access, so it cannot
  return more than row-level security allows. _Definer_ runs with elevated
  rights and checks the caller itself.
- "Staff: ops" means an active staff member with that role, or admin; and,
  when `require_staff_mfa` is on, a session with a second factor.
- A caller who is not allowed gets the error code `forbidden`, or — for
  something that belongs to another person — the same "not found" as if it did
  not exist.
- The typed client is `packages/db/src/api.ts`: each function has a camelCase
  method (`place_order` → `placeOrder`) and a response schema in `schemas.ts`.

## What is not a function

A few things are done by writing to a table directly, under a column-level
grant and a policy. They are part of the surface too.

| Operation                                                             | Table                                                       | Who                                              |
| --------------------------------------------------------------------- | ----------------------------------------------------------- | ------------------------------------------------ |
| Edit shop-front details                                               | `sellers` (trade name, description, logo)                   | Seller owners and admins                         |
| Edit contact, tax and payout details                                  | `seller_private` (selected columns)                         | Seller owners and admins                         |
| Add, change and remove team members, never an owner                   | `seller_members`                                            | Seller owners and admins                         |
| Edit listing content, images, variants                                | `products`, `product_images`, `skus` (content columns only) | Members of the listing's seller; catalogue staff |
| Withdraw a consent                                                    | `consents.revoked_at`                                       | Self                                             |
| Manage staff                                                          | `staff_members`                                             | Admin                                            |
| Manage drivers, warehouse staff, bins, zones, holidays, zone closures | Their tables                                                | Staff: ops                                       |
| Manage categories, brands, synonyms; moderate reviews                 | Their tables                                                | Staff: catalog (reviews: also support)           |
| Manage the fee schedule; record payouts                               | `fee_*`, `payouts`                                          | Staff: finance                                   |
| Change settings                                                       | `app_settings`                                              | Admin                                            |

The apps built so far use functions for everything they do; these direct
writes exist for the back-office screens and are covered by the access tests.

## Errors

A refused or failed call raises SQLSTATE `P0001` with a short machine-readable
code as its message, sometimes with a detail value (the offer that ran out,
the date a window closed). The complete list, with the text shown to a person
in Spanish and English, is `packages/db/src/errors.ts`. A unit test
(`errors.test.ts`) reads every `private.fail('…')` in the migrations and fails
if a code has no message or a message has no code.

The client turns any such failure into an `ApiError` with `code`, `detail` and
`userMessage(locale)`. Unexpected errors — a network failure, a response that
does not match its schema — become `network` or `invalid_response` and are
never shown verbatim.

Codes group roughly as:

| Group                    | Examples                                                                                                                                                              |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Who you are              | `not_authenticated`, `forbidden`, `not_a_driver`                                                                                                                      |
| Not found (or not yours) | `order_not_found`, `address_not_found`, `shipment_not_found`, `stop_not_found`, `review_not_found`                                                                    |
| Checkout                 | `cart_empty`, `offer_unavailable`, `insufficient_stock`, `price_changed`, `zone_not_served`, `cod_not_available`, `too_many_lines`, `invalid_quantity`                |
| State                    | `order_not_payable`, `too_late_to_cancel`, `invalid_shipment_state`, `picking_incomplete`, `route_not_startable`, `settlement_already_closed`, `invalid_return_state` |
| Rights with a deadline   | `withdrawal_window_closed`, `warranty_expired`, `not_delivered_yet`                                                                                                   |
| Input                    | `address_invalid`, `postal_code_invalid`, `invalid_listing`, `invalid_profile`, `reason_required`, `note_required_for_difference`                                     |
| Configuration            | `sandbox_disabled`, `no_active_fee_schedule`, `calendar_misconfigured`                                                                                                |

## Keeping this page honest

To list the functions and their grants as the database has them:

```sql
select p.proname,
       case when p.prosecdef then 'definer' else 'invoker' end as mode,
       has_function_privilege('anon', p.oid, 'execute') as visitors,
       has_function_privilege('authenticated', p.oid, 'execute') as signed_in
from pg_proc p
join pg_namespace n on n.oid = p.pronamespace
where n.nspname = 'public' and p.prokind = 'f'
order by 1;
```

At the time of writing: 77 functions, 10 of them open to visitors, all 77
callable by signed-in users subject to their own checks. A function in
`public` that appears here without a grant line in a migration, or a grant to
visitors that is not in the first table above, is a defect.
